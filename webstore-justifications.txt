QuickPaste Chrome Web Store - permission justifications (max 1000 chars each)
==============================================================================

--- Remote code (Are you using remote code?) ---
QuickPaste is a Manifest V3 extension and does not load, fetch, or execute any remotely hosted code. Every script that runs is bundled inside the .zip submitted to the Web Store: the service worker (background.js) and its importScripts targets (lib/storage.js, lib/format.js, lib/settings.js, lib/sync.js), the popup (popup.js plus lib/*), the options page (options.js plus lib/*), and the single content script (content/capture.js). All script paths are relative to the extension package. There are no <script src="https://..."> tags, no eval(), no new Function(), no import() of remote modules, no remotely hosted WebAssembly, and no chrome.scripting.executeScript calls that pass remote URLs. The "Send to" feature opens notion.so and docs.google.com in new tabs via chrome.tabs.create. Those are user navigations, not loaded code. No CDN, no analytics, no backend server.

--- clipboardWrite ---
QuickPaste uses clipboardWrite for an opt-in feature called "Auto-copy on save". When the user enables this toggle in Settings, the text of a clip just saved is written to the system clipboard so the user can paste it into another app without opening the popup. Because Manifest V3 service workers cannot access navigator.clipboard directly, the write is performed from a short-lived offscreen document (offscreen.html) that the service worker creates, instructs to write a single string, and then closes. The clipboard is only written in direct response to a user-initiated save action: never on a timer, never in the background, never with data the user did not personally select or copy. No clipboard reads are performed; the permission is used strictly for write-on-save. The feature is off by default, can be turned off at any time in Settings, and never transmits the clipboard contents anywhere. The write is purely local.

--- offscreen ---
QuickPaste uses the offscreen permission solely to create a hidden helper document (offscreen.html) that performs clipboard writes on behalf of the Manifest V3 service worker. In MV3, service workers do not have a DOM and cannot call navigator.clipboard, so any clipboard interaction must happen in a regular document context. The offscreen document is created on demand when the user's "Auto-copy on save" setting is on and a save has just occurred, receives a single string from the service worker via chrome.runtime messaging, writes that string to the clipboard, and is closed immediately afterwards. The offscreen page loads only one local script (offscreen.js bundled with the extension), makes no network requests, has no UI, and is never used for anything other than the clipboard write. It is not used for content extraction, scraping, audio/video, iframe rendering, or any other purpose offscreen documents can technically support.

--- alarms ---
QuickPaste uses the alarms API to implement the user's optional auto-delete retention setting. In Settings the user can choose to automatically remove clips older than a chosen window (for example, 7, 30, or 90 days), or leave the feature off. When the feature is enabled, the service worker registers a single chrome.alarms alarm that fires roughly once every 24 hours. When it fires, the service worker reads the user's retention window from chrome.storage, scans the local clip list, and deletes any unpinned clips whose savedAt timestamp is older than the threshold. Pinned clips are never removed. No network request is made, no data leaves the device, and no other periodic work is scheduled. The alarm is removed when the user turns retention off. The permission is used exclusively to wake the service worker for this housekeeping pass; it is not used for polling, syncing on a schedule, or any background fetching.

--- Host permission: <all_urls> (declared as optional_host_permissions) ---
QuickPaste does not request broad host access at install time. The manifest declares <all_urls> only as an optional host permission, and the extension prompts the user (via Chrome's native permission dialog) only when the user opts in to the auto-capture feature in Settings. The right-click "Save text" and "Save image" menu items work without any host permission because chrome.contextMenus.onClicked delivers selectionText, srcUrl, and pageUrl from the user's click gesture itself. Auto-capture, which observes local Ctrl+C / Cmd+C events to mirror copies into the user's own Collection, is off by default. Turning it on triggers a chrome.permissions.request call, after which a content script is dynamically registered via chrome.scripting. Turning auto-capture off unregisters the script. QuickPaste never reads page contents on its own, makes no network requests, and stores all data locally on the device (or in the user's own Chrome Sync if they enable it).

--- scripting ---
QuickPaste uses the scripting permission to dynamically register and unregister the single content script (content/capture.js) used by the opt-in auto-capture feature. The static content_scripts manifest entry has been removed so that QuickPaste does not inject anything into web pages by default; the script is only registered after the user enables auto-capture in Settings and grants the <all_urls> optional host permission via Chrome's native dialog. When the user disables auto-capture, the script is unregistered. The scripting API is also used once at toggle-on time to inject the same local content script (chrome.scripting.executeScript with the files parameter) into already-open tabs so the user does not need to reload them. No remotely hosted code, no string-based code, and no arbitrary URLs are ever passed to chrome.scripting; only the local content/capture.js file that ships in the extension package.
